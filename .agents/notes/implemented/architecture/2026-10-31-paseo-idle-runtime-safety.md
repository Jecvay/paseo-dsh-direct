# 决策记录: 查询 DSH 内部工作后再允许 Paseo 回收空闲运行时

Status: implemented

## 问题

Paseo 0.14 默认在满足宿主条件且空闲一小时后释放可恢复运行时。不提供 `session.can_stop_runtime` 的 Provider 不参与安全判断。DSH 原生后台任务和子代理可以在主会话空闲后继续运行；未登记为 Paseo 子会话的工作不在宿主的检查范围内。直接关闭 DSH 进程可能中断任务或丢失尚未送达的完成通知。

连接关闭时等待启动中的桥接，是另一项资源清理责任。它保证收到关闭指令后没有遗留进程，不能判断宿主此时是否应该关闭运行时。

## 决定

`@getpaseo/plugin` 开发依赖和 `@getpaseo/client`、`@getpaseo/protocol` 可选 peer 依赖固定为 `0.14.0`。清单保留 `requirements.paseo: ">=0.11.0"`，新查询通过连接和会话能力协商启用，旧宿主过滤未知能力。此决定遵循 [最低版本规则](../process/2026-10-11-raise-version-floors-only-on-real-incompatibility.md)，并补充 [Direct 桥接](2026-09-23-pi-tui-direct-bridge.md) 的生命周期契约，不替代其通信路线。

Provider 先检查持久会话已就绪，没有活动回合、分发、挂起交互或进行中的操作，再通过桥接的 `session.can_stop_runtime` 只读请求检查 DSH 内部工作。桥接关闭会退出整个 DSH 进程，因此检查该进程内全部 agent 的执行状态、inbox、活动目标和调度，以及全进程后台任务。原生子代理按 `subagent/start`、`subagent/end` 全局跟踪运行，覆盖本地 agent 表之外或无法归属会话的外部后端；完成通知送达父会话、子代理收尾完成后才解除保护。查询期间出现新活动时拒绝回收。

安全判断需要的检查接口缺失或失败时，结果为 `canStop: false`；普通会话仍可使用。肯定回复只表示允许宿主继续判断，查询本身不取消任务、不释放资源。实际关闭继续使用会话持久化、桥接释放及启动期清理路径。请求和回复格式见 [服务端架构](../../../../docs/server-architecture.md#空闲运行时回收)。

Paseo 0.14 的每 agent 工具和会话打开钩子注入的 MCP server，经宿主传入 `session.open.config.mcpServers` 与 `toolPolicy`，使用现有 DSH MCP 挂载及预批准机制。

## 考虑过的其他做法

1. **完全依赖宿主的空闲判断**：实现最少，但宿主看不到 DSH 原生后台工作，不能据此安全关闭进程。
2. **声明能力并始终返回 `false`**：可以保护工作，但所有会话都失去空闲回收收益。采用实际检查；只有无法确认安全时保留运行时。
3. **把最低 Paseo 版本提高到 0.14**：减少兼容组合，但旧宿主可以过滤新能力，普通会话没有依赖新接口，没有提高下限的必要。
4. **为每 agent 工具另建传输通道**：能自定义工具路由，但重复宿主已有的 MCP 机制，增加维护与权限处理路径。

## 后果

- 确认无待处理工作的持久会话可以参与宿主空闲回收，下一次输入仍由宿主恢复同一原生会话。
- 缺少必需检查接口的 DSH profile 保留运行时，代价是这些会话不能自动释放占用的资源。
- 自定义 profile 启动的其他 agent、后台任务和调度同样参与判断；不能只因 Paseo 对应的主会话空闲就关闭整个进程。
- 查询检查与关闭清理分别负责是否允许关闭、关闭后释放资源；启动途中关闭连接的清理逻辑保持有效。
- 新的 DSH 任务类型若不在现有检查接口和事件范围内，仍需要补充审查；仅有主 agent 的 `idle` 状态不足以证明可安全停止。

## 怎么验证的

Paseo SDK 0.14.0 与 0.11.0 的真实发布包已交叉验证能力协商。构建、四组类型检查及回归测试通过；DSH 0.2.1-rc.4 的桥接 smoke 返回 10 个模型和 495 条原生历史摘要并正常关闭。隔离原生设置 E2E 不请求模型，验证设置初始化、持久化、过期草稿拒绝和会话策略保留。

隔离的 Paseo 0.14.0 Daemon（真实 `@getpaseo/server`/`client` 0.14.0、真实 DSH 0.2.1-rc.4、loopback 脚本模型、临时 home）验证了完整模型回合、空闲时钟快进一小时后的回收与 DSH 子进程关闭、后台任务运行期间拒绝回收、以及回收后下一条消息与 `agent.reload()` 恢复同一原生 `sessionId`；`session_open` 注入的 MCP server 与每 agent 工具出现在模型可见工具中。安全查询是点查询：宿主收到肯定答复后到实际关闭之间新开始的工作，属于 Paseo 协议本身的竞态，插件无法用公开接口消除。最终版本组合和实测边界以 [兼容性说明](../../../../docs/compatibility.md) 为准。

# Alpha 验收规范

首版 alpha 的验收对象是本机 Paseo 中的 `dsh-pi` Direct Provider，以及它启动的 `paseo` profile。版本配对见 [兼容性说明](compatibility.md)。

## 数据与配置边界

- 复用用户的 DSH home、凭证和历史会话；模型配置读取 `paseo` profile 的用户层 `cordis.patch.yml`。
- 不修改 Paseo 或 DSH 核心，不把历史会话转换成另一份独立聊天记录。
- `paseo` profile 缺失时由插件用官方 `web` 模板创建一次；之后插件不改写 profile 文件。启动覆盖只作用于本次子进程，不将凭证或本机私有配置写进插件仓库。
- 历史读取和恢复保留原生会话标识；同一会话不能被多个插件子进程同时写入。
- 自动化测试使用临时目录和合成历史；真实环境验证使用专用测试会话，避免向用户已有工作会话写入测试内容。

## 必须通过的行为

| 场景 | 通过标准 |
|---|---|
| 安装与注册 | 本地安装成功，插件状态正常，Paseo 可发现 `dsh-pi` Provider |
| 配置与历史 | 缺失时自动创建 `paseo` profile，已存在时直接使用；可选择并读取原生历史会话，恢复后的提示词沿用同一会话 |
| 文本与思考 | 流式文本与思考保留原文、缩进和重复空白；相邻分片合并显示，不产生逐 token 气泡，定稿不重复追加已显示文本 |
| 工具与审批 | 工具开始、完成、失败可见；审批允许或拒绝都能结束等待 |
| 中断 | 用户停止后当前回合结束，可以继续发送下一条消息 |
| 重启恢复 | 插件连接或 DSH 子进程重建后可重新打开持久化会话 |
| 异常退出 | 子进程崩溃、协议错误或超时不会留下永久运行的回合或审批 |
| 隔离与清理 | 客户端不依赖 Node/DOM；关闭连接清理子进程和等待中的请求；启动途中关闭连接也不遗留桥接进程 |
| 空闲回收查询 | Paseo 0.14 协商 `session.can_stop_runtime`；该 DSH 进程内任一 agent 仍在执行，或仍有交互、后台任务、原生子代理、活动目标、调度及排队工作时拒绝回收，包含自定义 profile 自启的工作；检查接口缺失、检查失败和查询期间新活动均不能放行；Paseo 0.11 不协商该能力时普通会话正常 |
| 空闲回收与恢复 | 确认无待处理工作的持久会话允许回收；宿主随后关闭运行时，下一条消息恢复同一原生 DSH 会话；查询本身不改变会话或停止进程 |
| 会话工具注入 | 宿主经 `session.open.config.mcpServers` 提供的每 agent 工具和会话打开钩子注入的 MCP server 可通过现有 MCP 挂载路径调用，工具预批准遵循 `toolPolicy` |

## 桥接就绪等待验收

以下是候选必须满足的标准；表中场景不表示已通过。结果须注明候选 HEAD、Paseo/DSH 版本、运行平台、计时起止信号与实际观察。

| 场景 | 通过标准 |
|---|---|
| 默认与解析 | 留空/纯空白保持 15 秒；1 和 600 接受；0、601、小数及非数字拒绝；非法文本仅回退超时项，保留 executable/profile，诊断不回显输入 |
| 两处入口与热读 | Provider `createBridge` 与子代理设置 `open` 都读取新值；会话创建/恢复、目录/历史发现、设置读写的新桥接均使用它；已有桥接保持原值，目录缓存身份不变 |
| 可控延迟 | 同一个受控子进程延迟在短窗口内报错、在长窗口内收到 `bridge.ready` 并完成初始化；至少一例 ready 延迟超过默认 15 秒，不能只断言源码或参数透传 |
| 超时与清理 | 永不 ready 的进程按配置窗口失败，子进程退出且临时目录删除；ready 前退出快速失败；启动途中关闭、迟到桥接及并发关闭沿用既有清理回归；插件卸载取消各阶段尚未完成的启动，在宿主强制终止前回收自有子进程及临时目录 |
| 阶段边界 | profile 创建 60 秒、配置检查 20 秒位于 ready 窗口前；`bridge.initialize` 的 30 秒位于其后；ready 后初始化卡住不会使用 ready 窗口继续等待 |
| 宿主外层时限 | 分别核对最低 Paseo 0.11、开发 SDK 对应 0.14 及 0.15.3 的固定 runtime 源码；在各版本的隔离宿主验证 Provider connect/普通插件 RPC 的 30 秒边界，以及已连接 `session.open` 超过 30 秒后仍能就绪的事件路径；未运行的版本单列为未验证。0.15.3 隔离探针已覆盖，0.11/0.14 尚未运行 |
| 超时后保存 | 受控延迟的子代理设置保存触及宿主 RPC 超时后，观察底层任务及持久配置是否仍会提交；重新读取状态后再决定是否重试，不把 UI 超时报错当作未写入的证据 |
| 真实 DSH | 临时 home/profile 下完成就绪、初始化与关闭，不调用收费模型；计时从桥接进程 spawn 到 `bridge.ready`，浏览器就绪日志不能替代；没有并发慢启动复现时明确记录未知 |

宿主源码与各段时限见[服务端架构](server-architecture.md#桥接就绪等待与宿主时限)。600 秒是策略上限，通过受控延迟测试不代表生产环境需要或已验证等待 600 秒。Windows shim 的 stdin EOF 死锁由启动路径处理，延长就绪等待不能修复死锁。

## 证据要求

类型检查、协议与生命周期测试、文档门禁均须通过。本机安装、真实运行和重启恢复的结果记入本地 `.agents/ops-log.md`，该文件由 Git 忽略、按需创建；记录只包含版本、命令、结果和必要的脱敏标识，不包含凭证或完整对话。Agent 自行将可复用结论核实、脱敏后整理进长期文档，只提交长期产物。判断是否通过仍以本规范的验收标准为准。

自动化测试通过不等同于所有平台实测通过。发行说明必须明确区分 Linux Daemon 验证、真实模型验证，以及尚无真机证据的平台。

# Alpha 验收规范

首版 alpha 的验收对象是本机 Paseo 中的 `dsh-pi` Direct Provider，以及它连接的既有 `pi-tui` profile。版本配对见 [兼容性说明](compatibility.md)。

## 数据与配置边界

- 复用用户选择的 DSH home、`pi-tui` profile、模型配置和历史会话。
- 不修改 Paseo 或 DSH 核心，不把历史会话转换成另一份独立聊天记录。
- 启动覆盖只作用于本次子进程；不覆盖用户的 profile 文件，不将凭证或本机私有配置写进插件仓库。
- 历史读取和恢复保留原生会话标识；同一会话不能被多个插件子进程同时写入。
- 自动化测试使用临时目录和合成历史；真实环境验证使用专用测试会话，避免向用户已有工作会话写入测试内容。

## 必须通过的行为

| 场景 | 通过标准 |
|---|---|
| 安装与注册 | 本地安装成功，插件状态正常，Paseo 可发现 `dsh-pi` Provider |
| 配置与历史 | 使用既有 profile；可选择并读取原生历史会话，恢复后的提示词沿用同一会话 |
| 文本与思考 | 使用稳定 item 标识和累计快照，流式过程中不产生逐 token 气泡 |
| 工具与审批 | 工具开始、完成、失败可见；审批允许或拒绝都能结束等待 |
| 中断 | 用户停止后当前回合结束，可以继续发送下一条消息 |
| 重启恢复 | 插件连接或 DSH 子进程重建后可重新打开持久化会话 |
| 异常退出 | 子进程崩溃、协议错误或超时不会留下永久运行的回合或审批 |
| 隔离与清理 | 客户端不依赖 Node/DOM；关闭连接清理子进程和等待中的请求 |

## 证据要求

类型检查、协议与生命周期测试、文档门禁均须通过。本机安装、真实运行和重启恢复结果记录于 `.agents/ops-log.md`；记录只包含版本、命令、结果和必要的脱敏标识，不包含凭证或完整对话。

自动化测试通过不等同于所有平台实测通过。发行说明必须明确区分 Linux Daemon 验证、真实模型验证，以及尚无真机证据的平台。
